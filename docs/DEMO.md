# Demo route

1. Run the whole Node deployment, not just the static frontend.
2. Save a profile with a peanut allergy; the peanut tofu recipe disappears. Change age/activity inputs and inspect the sourced energy calculation.
3. Log or remove some spinach so it falls below its learned minimum. Open Groceries: the gram shortage is generated. Complete it, switch the dropdown to Completed, restore it, or clear its history.
4. In Containers add a photo, inside dimensions, copy count, and owner. A measured density override is optional.
5. Connect both camera phones using separate temporary camera codes. Enable analysis with your server key and consent. Capture a reference scene, then a settled food movement. Observe either one automatic transaction or an explicit review reason.
6. In a second main app/browser with its own owner session, enable friend sharing. Exchange a friend invitation through My fridge, then view its real shared inventory and shared challenge awards.
7. Request a friend's food free or offer your own. On the recipient app accept/decline. Check that stock is unchanged until the physical exchange is recorded.
8. In Meal plans → Cook together select shared fridges and save a realistic plan. Review ingredient coverage, portions, and the source recipe.
9. Cook/log a personal recipe and inspect all 152 nutrient fields and data coverage. Challenge points come from recorded actions once; change the leaderboard period.
10. Open Food Wrapped for that month. It has nutrition totals and food/cuisine patterns, with no streak or points section.

Ava/Allen remain labelled local sample fridges. No fake camera food, fabricated friend score, or provider response is injected into the normal app. Automated tests use isolated fixtures/stubs without changing this behavior.
